# 操作紀錄

## 目前的精簡版

系統已將刪除訂單、修改每日實收、刪除支出及清除測試資料記入 `audit_events`。
紀錄包含時間、操作種類、對象及前後摘要；與原操作在同一 SQLite 交易提交，
清除測試資料不刪除此表。管理員可在「整體設定 > 操作紀錄」查看最近 200 筆。
摘要不儲存客戶姓名、電話、實收備註或支出備註。新增支出本身仍由支出明細記錄。

目前共用一個管理員身分，不能從紀錄辨認是哪位員工操作。本機資料庫管理者
仍可直接修改紀錄，因此這是日常追查輔助，不是防竄改的正式稽核系統。

## 未來可擴充的設計

## 記錄範圍

- 刪除訂單：品項、數量、原金額、是否已付款、原因。
- 修改實收、費率及優惠：修改前後的值、原因。
- 退款：未來新增退款功能時，記錄原付款編號、退還金額、原因；不可直接刪除原付款。
- 清除資料：清除範圍、筆數、備份檔名及校驗碼、操作結果。
- 管理員登入失敗、登出、變更密碼：只記事件，不記密碼、密碼雜湊、Cookie 或 Token。

## 儲存方式

若日後需要個人責任歸屬，可新增員工個人登入或 PIN、原因欄位、事件 UUID、
前後值 JSON、關聯操作編號及防竄改的離機副本；這些都不是目前精簡版的功能。

一般異動與稽核紀錄必須在同一 SQLite 交易提交；異動失敗不可留下成功紀錄。失敗嘗試可另記安全日誌並輪替。重送請求不得重複產生業務或稽核紀錄。

清除營運資料不清除 audit_events。清除前先備份，成功交易中追加清除摘要；不保留被刪除資料的姓名、電話等完整內容。系統只提供查閱與匯出，不提供修改或刪除稽核紀錄的入口。

## 權限與限制

目前查看頁限管理員登入，顯示最近 200 筆；日期及類型篩選、匯出與強制填寫原因仍待日後需求確認。

目前共用一個管理員身分、員工不用登入，因此只能確認角色與工作階段，不能可靠聲稱是哪位員工操作。若需追蹤個人，須額外設計個人登入或個人 PIN。

資料庫檔案擁有者仍可繞過應用程式直接修改 SQLite。若要求防竄改，需離機保存附簽章的稽核副本，不能只靠本機唯讀介面。

## 保留與隱私

不記敏感登入資料；姓名與電話預設遮罩。保留期限、匯出權限及定期封存方式需由球館決定；不直接新增永久保留政策。
