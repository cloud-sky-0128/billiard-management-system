# Windows 下載版發布驗收清單

目標：讓使用者從 GitHub Release 下載 ZIP、解壓後在自己的 Windows 電腦使用。不需要 Microsoft Store，也不要求先做安裝程式。瀏覽器版與獨立視窗版分開驗收；獨立視窗版在通過全部必要項目前維持「預覽版」。

請使用**非營業測試資料**。不要在正式資料庫上做清除資料、故障模擬、還原或強制終止測試。本文件是每次發布前的簽收表，不代表目前版本已通過所有項目。

## 1. 下載與檔案（必要）

- [ ] 從 GitHub Release 的正式連結下載本次 ZIP；記錄版本標籤，不使用開發資料夾中的 EXE 代替。
- [ ] 用 `Get-FileHash -Algorithm SHA256 .\下載的檔名.zip` 比對**同一個 Release** 的 `SHA256SUMS.txt`。
- [ ] 完整解壓後有對應的 `BilliardManager.exe` 或 `BilliardManagerWindow.exe`，以及正確版本的 `README.txt`。
- [ ] ZIP 不含 `billiard.db`、備份、日誌、測試客戶資料、密碼或建置憑證。
- [ ] 發布頁明確區分瀏覽器版與獨立視窗版，列出已知限制：尚未連接實體燈控。

## 2. 乾淨電腦啟動（必要）

- [ ] 在沒有安裝 Python、沒有專案原始碼的 Windows x64 電腦上，以一般使用者帳戶從解壓資料夾啟動。
- [ ] 首次啟動顯示介面，所有主要頁面可開啟；不依賴 `C:\Users\forev` 或開發機上的檔案。
- [ ] 使用者能找到資料庫、備份和錯誤日誌位置；關閉後重新啟動，資料仍在。
- [ ] 斷開網際網路後仍可開啟並操作已安裝好的程式；本機網址是 `127.0.0.1:8765`，不是公開網路服務。
- [ ] 重複開啟程式、8765 連接埠已被占用、資料目錄不可寫時，能看到可理解的提示，不會悄悄建立另一份空白資料庫。
- [ ] 關閉視窗或程式後，本機服務停止；再次啟動可正常使用。
- [ ] 獨立視窗版：分別在已有 WebView2 Runtime、尚未安裝 Runtime 的電腦驗證。缺少時要有明確提示；需要完全離線部署時，另備 Microsoft 官方的 Runtime 離線安裝程式。

## 3. 球館日常流程（必要）

- [ ] 計時開桌、換桌、點餐、分次收款、結帳後，桌況、付款紀錄和營業統計相符。
- [ ] 包台開桌、加時、換桌、提前結束與結帳後，已收與待收金額正確，沒有重複收款。
- [ ] 免費練習只標示使用中，不產生球檯費；目前**不會**控制實體燈具。
- [ ] 同一表單連點、重新整理或重送，不會造成重複點餐、加時或支出。
- [ ] 未分桌點餐、分配球桌、只結餐飲費等流程可完成。
- [ ] 預約同桌衝突、無結束時間保留一小時、跨午夜與每分鐘時間選擇皆符合預期。
- [ ] 員工排班、個人班表 PNG、每日實收、支出與 CSV 匯出結果正確。
- [ ] 在 05:59 和 06:00 前後的測試收款歸屬到正確營業日；折扣與收款按整元處理。

## 4. 升級與資料安全（必要）

- [ ] 先複製舊版**測試資料庫**，記錄預約、收款、班表與設定數量，再用新版 ZIP 啟動；升級後資料完整，舊版資料表可正常遷移。
- [ ] 升級前手動建立備份並執行還原演練；另用**測試副本**完成一次實際還原，確認不是只有備份檔存在。
- [ ] 模擬同一位置已有資料庫、兩個候選位置各有資料庫、資料目錄不可寫；程式不得靜默改用新資料庫。
- [ ] 使用測試資料驗證 15 分鐘快照的時間與警告；另確認備份複製到其他磁碟或外接儲存設備。程式關閉期間不會自動備份。
- [ ] 在**測試副本**上強制結束程式或模擬中斷，重新啟動後檢查資料庫完整性，以及未完成交易沒有留下半筆收款。
- [ ] 記錄回退步驟：先停止程式、另存新版資料庫，再還原升級前備份；明確告知回退可能失去備份之後的紀錄，舊程式不一定能讀新版資料庫。
- [ ] 若舊版資料放在 EXE 旁的 `data`，確認換 ZIP 時一併保留；不得只複製新 EXE 而遺失資料。

## 5. 自動測試與安全（必要）

- [ ] GitHub 對本次提交的測試工作流程成功；對應 Windows 標籤的打包工作流程成功，並確認 Release ZIP 實際可下載。
- [ ] 至少一次從**下載的 ZIP** 啟動，而不只執行 Python 原始碼測試；瀏覽器版與視窗版分別驗證。
- [ ] 以正常安全設定測試管理員登入、密碼錯誤、權限失效、CSRF 拒絕與高風險操作紀錄。
- [ ] 使用者輸入異常金額、日期與包台時數時，顯示欄位錯誤，不出現伺服器錯誤頁。
- [ ] 確認測試資料、資料庫、備份及日誌沒有上傳到 GitHub；下載者知道備份可能含客戶資料，必須妥善保管。

## 6. 交付與支援（必要）

- [ ] README 寫清楚下載、解壓、啟動、停止、資料位置、WebView2 需求、備份與回退，不把預覽版寫成正式穩定版。
- [ ] 記錄已知問題、測試範圍、遇到錯誤時如何提供版本號與日誌；提供聯絡或回報方式。
- [ ] 對外說明目前是**單機版**：每台電腦各有自己的資料庫，沒有跨電腦同步，也沒有無線燈控整合。
- [ ] 指定一個已驗收的 ZIP 作為建議下載版本；保留舊版 Release 與備份，不覆蓋原檔。

## 可後續改善，不阻擋少量使用者下載 ZIP

- [ ] 製作安裝程式、桌面捷徑與自動更新；在此之前維持清楚的手動升級步驟。
- [ ] 程式碼簽章與更完整的發行者資訊；在此之前如實說明未簽章及 Windows 可能顯示警告，不能把 SHA-256 當成簽章。
- [ ] 鎖定全部間接相依套件、在 CI 執行套件弱點檢查及打包後端到端測試。
- [ ] 依實際維護痛點逐步拆分過大的 Blueprint，不為了「看起來架構漂亮」而一次重寫所有功能。
